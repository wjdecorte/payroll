# M3 Expenses Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Vendors, expenses with split lines and receipts, transfers, and owner reimbursement, all posting to the ledger, released as v2.3.0.

**Architecture:** A new `payroll/expenses/` package mirrors `payroll/receivables/`: each document row (expense, transfer, reimbursement) posts exactly one journal entry through `LedgerPostingService`, commits through the shared rollback-on-any-error wrapper, and voids by reversal. Integrity is enforced in the database (CHECKs, deferred constraint triggers) as in M2. Receipts go through a generic, append-only attachment store on disk. Pages live in `payroll/frontend/expense_routers.py`.

**Tech Stack:** FastAPI, SQLModel, Alembic, Postgres 17, Jinja2 + HTMX, Python 3.14, uv, ruff, pytest, Hypothesis, WeasyPrint (PDF).

**Spec:** `docs/superpowers/specs/2026-11-05-m3-expenses-design.md` (binding; this plan argues from it). Also `docs/SPEC.md` §4.4, F8, S4, S6.

## Global Constraints

- Python 3.14, `uv` only (never `pip`/`poetry`); `ruff check` and `ruff format` clean; `pre-commit` passing.
- Run the full suite before a task is done: `uv run pytest` (needs the test DB at localhost:5433, container `payroll-test-db-1`). Never run two pytest runs at once on that DB. Coverage must not drop below the current level.
- Money is `Decimal`, strict 2-decimal positive amounts through the M2 amount parser, maximum 100,000,000.00. Enum-like columns are plain strings with CHECKs.
- Every mutation: owner-only (`ensure_role(actor, OWNER)` in the service), audited via `record_audit`, CSRF-protected on the route, validation errors are 422 never 500.
- Posting goes through `LedgerPostingService`; reversals via `LedgerPostingService.void`, which respects the lock date. Void dates are on or after the document date (`check_void_date`).
- Locking order: role account row FOR SHARE (`bind_role` takes it FOR UPDATE), then document rows FOR UPDATE in id order, then the period lock FOR SHARE (inside posting), then the per-source entry counter.
- Memo cap 500 characters, payee text and vendor name cap 200, control characters refused, all text trimmed. CSV output goes through `csv_safe`.
- Every new POST route is added to the route-protection sweep (`tests/auth/test_route_protection.py`) in the task that adds it, with viewer, accountant, anonymous and no-CSRF cases.
- Do not push, open PRs, or edit ProjectOS inside a task; the controller does that.
- Commit after each task with a conventional message ending `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

Behaviors the spec implies and a person would hit, each pinned by a named test in its owning task:

1. Two reimbursements racing for the same expense: exactly one wins (Task 6, real two-session test, mutation-checked).
2. A reimbursed expense cannot be voided until its reimbursement is voided; voiding the reimbursement reopens it (Task 6).
3. A `.pdf`-named executable is refused and an oddly named real PDF is accepted; path traversal and RTL filenames cannot escape or confuse storage (Task 7).
4. Credit-card flow: card expense, then a transfer paying the card, brings the card to zero, and voiding the transfer restores it (Task 5).
5. "Owed to me" equals Due to Owner on clean data, and a manual journal on that account produces the mismatch note instead of a wrong number (Task 6).
